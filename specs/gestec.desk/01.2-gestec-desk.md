## 1. Objetivo

Exibir de forma legível o **resultado da última auditoria em massa** executada na spec [01](01-gestec-desk.md).

Abre ao clicar em **Visualizar** no card Auditoria em Massa. Mostra KPIs agregados e, na listagem, **somente estações com severidade média ou alta** — estações `low` entram nos KPIs, mas **não** aparecem nos cards detalhados.

## 4. Dados exibidos

### 4.1 KPIs (fonte: `result.total`)

Exibem **todas** as estações auditadas, inclusive severidade baixa:

| KPI | Campo API |
|-----|-----------|
| Estações | `total.stations` |
| Com alterações | `total.withChanges` |
| Severidade alta | `total.high` |
| Severidade média | `total.medium` |
| Severidade baixa | `total.low` |

### 4.2 Cards de estação (fonte: `result.items[]`)

**Filtro na UI (obrigatório):** renderizar apenas itens onde `item.summary.severity` ∈ `{ 'medium', 'high' }`.

| Campo | Origem | UI |
|-------|--------|-----|
| Hostname | `item.hostname` | Título bold |
| Usuário atual | `item.currentUser` | "Usuário atual: **xxx**" |
| Badge | `item.summary.severity` | `MEDIUM` / `HIGH` |
| Snapshots | `item.summary.snapshots` | Número |
| Alterações | `item.summary.changeCount` | Número |
| Hardware | `item.summary.changedHardware` | Sim / Não |
| Usuário | `item.summary.changedUser` | Sim / Não |
| IP | `item.summary.changedIp` | Sim / Não |

**Ordem sugerida:** `high` primeiro, depois `medium`; hostname ASC dentro de cada grupo.

### 4.3 Tabela de evidências (por estação)

| Coluna | Campo | Formato |
|--------|-------|---------|
| Categoria | `evidence.category` | `user`, `hardware`, `ip` |
| Campo | `evidence.field` | ex.: `Hardware.Cpu` |
| Antes | `evidence.previous` | monospace / JSON |
| Depois | `evidence.current` | monospace / JSON |
| Detectado em | `evidence.detectedAt` | `dd/mm/aaaa, hh:mm` |
| Severidade | `evidence.severity` | Badge `low` / `medium` / `high` |

> Na tabela de evidências podem aparecer linhas `low` (ex.: mudança de IP) mesmo quando a estação está na lista por ter outra evidência `medium`/`high`.

## 5. Origem das severidades

> **Seção crítica para implementação** — severidades **não são definidas na UI**. São calculadas no **backend** ao executar a auditoria, reutilizando a lógica de `auditService.js` do desk panel.

### 5.1 Fluxo de dados

```
Spec 01 — botão Executar
    ↓
POST /api/v1/gestec-desk/audit/bulk
    ↓
Para cada estação: busca histórico de inventários no período (Cosmos)
    ↓
auditStation(history) — compara snapshots consecutivos
    ↓
Retorna { summary, evidences } por estação + total agregado
    ↓
Armazena em sessionStorage (gestec-desk:last-bulk-audit)
    ↓
Spec 01 — botão Visualizar → esta página lê e renderiza
```

Esta página **não recalcula** severidade — apenas **consome** o payload já retornado pelo POST.

### 5.2 Severidade por evidência (`evidence.severity`)

Cada alteração detectada entre dois snapshots consecutivos recebe severidade fixa:

| Categoria | Campo | Condição | Severidade |
|-----------|-------|----------|------------|
| `user` | `System.UsuarioLogado` | Usuário logado mudou | **medium** |
| `hardware` | `Hardware.Cpu` | CPU mudou | **high** |
| `hardware` | `Hardware.Memoria` | RAM/slots mudaram | **medium** |
| `hardware` | `Hardware.Discos` | Discos mudaram | **high** |
| `hardware` | `System.BIOS/PlacaMae` | BIOS/placa-mãe mudou | **high** |
| `ip` | `Network.Ipv4` | IPs adicionados/removidos | **low** |
| `ip` | `Network.Policy` | IP fora das faixas corporativas (`CORPORATE_IP_RANGES`) | **medium** |

Implementação: função `changesBetween()` + evidência de política de IP em `auditStation()`.

### 5.3 Severidade geral da estação (`summary.severity`)

Calculada por `evaluateOverallSeverity(evidences, ipOutsidePolicy)`:

1. Inicia em `low`.
2. Para cada evidência, assume a **maior** severidade encontrada (`low` < `medium` < `high`).
3. Se houver IP fora da política corporativa e a severidade atual for `low`, eleva para `medium`.

**Exemplo:** estação com mudança de IP (`low`) + mudança de CPU (`high`) → severidade geral = **`high`**.

### 5.4 Totais agregados (`result.total`)

Calculados no handler `POST /api/v1/gestec-desk/audit/bulk` (igual ao panel):

| Campo | Regra |
|-------|-------|
| `stations` | Quantidade de estações auditadas |
| `withChanges` | Estações com `summary.changeCount > 0` |
| `high` | Estações com `summary.severity === 'high'` |
| `medium` | Estações com `summary.severity === 'medium'` |
| `low` | Estações com `summary.severity === 'low'` |

### 5.5 Filtro desta página vs. panel legado

| Aspecto | Panel legado | Gestec (esta spec) |
|---------|--------------|-------------------|
| Lista de estações | Todas | Apenas `medium` e `high` |
| KPIs | Todos os totais | Idem (inclui contagem `low`) |
| Cálculo de severidade | Backend | **Mesmo backend** — sem alteração |

**Implementação do filtro:** client-side sobre `result.items` antes do render — **não** alterar o payload armazenado.

```ts
const visibleItems = result.items.filter(
  (item) => item.summary.severity === 'medium' || item.summary.severity === 'high'
);
```

### 5.6 Configuração de IP corporativo

Variável de ambiente `CORPORATE_IP_RANGES` (CIDRs separados por vírgula). Se vazia, regra de IP fora da política **não** gera evidência `Network.Policy`.

## 7. Transporte de dados

Ao clicar **Visualizar** na spec 01:

1. Gravar em `sessionStorage` chave `gestec-desk:last-bulk-audit`:
   ```json
   {
     "executedAt": "ISO8601",
     "result": { "total": {}, "items": [] }
   }
   ```
2. `router.push('/gestec-desk/auditoria/resultado')`
3. Esta página lê, valida e renderiza.

Se `sessionStorage` vazio ou JSON inválido → `redirect('/gestec-desk')` + toast: *"Execute uma auditoria antes de visualizar."*

**Não** fazer nova chamada à API nesta tela (fluxo normal).

## 8. Integrações / API

| Operação | Quando | Endpoint |
|----------|--------|----------|
| Auditoria em massa | Spec 01 — Executar | `POST /api/v1/gestec-desk/audit/bulk` |
| Leitura do resultado | Esta página | `sessionStorage` (sem API) |

**Payload de entrada do POST (spec 01):**
```json
{
  "hostnames": ["DESKTOP-A"] ,
  "from": "2026-04-01T00:00:00",
  "to": "2026-04-30T23:59:59"
}
```
`hostnames` null/ausente = todas as estações.

**Response (trecho por estação):**
```json
{
  "total": {
    "stations": 10,
    "withChanges": 4,
    "high": 1,
    "medium": 2,
    "low": 1
  },
  "items": [{
    "hostname": "DESKTOP-A",
    "currentUser": "joao",
    "summary": {
      "snapshots": 5,
      "changeCount": 2,
      "changedHardware": true,
      "changedUser": false,
      "changedIp": false,
      "severity": "high"
    },
    "evidences": [{
      "category": "hardware",
      "field": "Hardware.Cpu",
      "previous": {},
      "current": {},
      "detectedAt": "ISO8601",
      "severity": "high"
    }]
  }]
}
```

**Backend:** migrar/reutilizar `auditService.js` em `src/controllers/gestec-desk/` ou lib interna equivalente.
